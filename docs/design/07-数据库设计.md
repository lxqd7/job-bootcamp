# 数据库设计

日期：2026-11-17。此处是建表契约，开发模型据此编写Flyway SQL，不照搬旧库。所有字段不带?均NOT NULL；?允许NULL。以下列出业务字段及约束，通用字段按本节统一展开。

## 1. 通用约定

- MySQL 8.0.34（2026-11-19 用户确认固定为本机开发基线，替代原 8.4.7）、InnoDB、utf8mb4/utf8mb4_0900_ai_ci；业务键/令牌哈希使用ascii_bin或binary排序。各服务bc_*库隔离。不使用 8.4 专属语法；Flyway 兼容性由 S01-b 实际迁移验证。
- 普通表id BIGINT UNSIGNED自增；业务跨库ID传字符串，SQL按数值排序。不能由前端number承载64位ID。复合主键表无需重复id。
- 所有可变表带created_at/updated_at DATETIME(3) UTC、revision BIGINT默认0；不可变版本/流水仅created_at。行内已列出的通用字段只建一次。命名_snake_case，API camelCase。
- 类型缩写：ID=BIGINT UNSIGNED；M=BIGINT（分，CHECK>=0）；P=BIGINT（积分，余额非负、流水增量可负）；T=DATETIME(3)；S=VARCHAR(32)状态；J=JSON；B=BOOLEAN。name/title默认VARCHAR(200)，所有*_hash为CHAR(64)，request_key为VARCHAR(64)，reason为VARCHAR(1000)。金额/积分接口绝对值不得超过9007199254740991（JS安全整数），后端边界校验、加法溢出检查及BigInteger中间乘积必须具备；不得用double计算。
- 业务状态用VARCHAR＋应用枚举＋CHECK，不用难扩展的SQL ENUM。FK仅允许本服务本库；跨库存ID/版本/快照并由契约校验。不级联删除交易、作答、积分、权益来源。
- U()唯一索引，I()普通索引；除明确的“非空值唯一”约束（formal_scope_key、source_note_id、active_order_id）外，不依赖NULL参与唯一判重；这三类允许多行NULL，是有意使用MySQL语义。复合软删除唯一关系使用稳定行＋状态复用，不通过重复插入绕过。
- JSON仅用于不可变结构/快照与schema已定义的文档，不把需并发扣减或筛选的余额/库存藏在JSON。
- 更新接口带revision，UPDATE WHERE id AND revision，成功+1，否则409；对金额/库存用行锁或条件更新，不依赖泛用saveOrUpdate。
- 性能索引按下列查询模式实现，分页稳定排序（createdAt,id）；不得无条件全表扫描后Java过滤权限。
