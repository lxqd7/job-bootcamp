# 工程架构与版本基线

日期：2026-11-17。本文确定实施方案；版本已发布不等于本项目已编译通过。阶段S01/S02执行验证并保存日志，不重新选择业务规则。

## 1. 工程与服务

根目录 job-bootcamp；后端 `backend/pom.xml`，包名 `com.jobbootcamp`。每服务按 controller/application/domain/infrastructure 分包，不为简单CRUD机械创建多层转换。公共模块只放错误、鉴权、事件封装，禁止共享业务实体或Mapper。

| Maven模块 | 端口 | 独占逻辑库 | 职责 |
|---|---:|---|---|
| bootcamp-gateway | 18080 | 无 | 路由、入口JWT、CORS |
| bootcamp-user | 18081 | bc_user | 账号、单角色RBAC、会话 |
| bootcamp-course | 18082 | bc_course | 课程、媒体、路线版本、教师分配、MySQL搜索 |
| bootcamp-learning | 18083 | bc_learning | 权益来源、进度、路线历史资格、退款申请顺序 |
| bootcamp-trade | 18084 | bc_trade | 报价、订单、支付、抵扣关联、退款协调 |
| bootcamp-assignment | 18085 | bc_assignment | 题目版本、作答、AI任务 |
| bootcamp-interaction | 18086 | bc_interaction | 问答、笔记、点赞、优秀评选 |
| bootcamp-marketing | 18087 | bc_marketing | 券、签到、积分、月榜、兑换 |

`bootcamp-common`为普通jar；`bootcamp-contracts`只放内部DTO与事件schema，生产者拥有契约。支付不另建服务；AI不另建服务；教师复用管理前端。

前端两个应用：`frontend/student`（15173）、`frontend/admin`（15174）；Vue Router按角色生成菜单，服务端仍验权。npm workspace根锁文件唯一，构建输出分开。根目录另有 `scripts`、`config/examples`、`tests/acceptance`，文档保留在docs。

各库仅由所属服务连接；可共用一个独立MySQL实例，不跨库SQL、外键或事务。已有旧实例不得覆盖配置或清空数据。

## 4. 鉴权与通用协议

一个账号一个角色 STUDENT/TEACHER/ADMIN，不自动兼任。注册只创建学生；教师由管理员创建/分配；管理员由种子初始化，不开放公共管理员注册。登录使用用户名＋密码，用户名4～32个字母数字下划线、密码8～72字节；昵称1～30字符。密码BCrypt，不将原文写日志。演示账号密码通过本地种子参数提供。

Access JWT RS256，有效15分钟，claims=sub/role/sessionId/tokenVersion/iss/aud/exp/jti；refresh随机256位、哈希存库，有效7天、HttpOnly/SameSite=Lax cookie，刷新轮换、旧令牌复用撤销会话。另设JS可读的csrf cookie（随机值，服务端仅存hash），刷新/退出请求以X-CSRF-Token提交；页面重新加载后可从csrf cookie恢复刷新流程，不读取HttpOnly refresh。生产两类cookie均Secure、SameSite=Lax，refresh Path=/api/v1/auth，csrf Path=/；cookie名称分别为bc_student_refresh/bc_student_csrf和bc_admin_refresh/bc_admin_csrf；不能依赖端口隔离cookie。登录clientApp决定会话域并校验STUDENT或TEACHER/ADMIN角色，前端固定发送对应X-Client-App，服务端验证与session一致。登出撤当前会话；角色/禁用/改密递增tokenVersion并撤销全部会话，改密成功后重新登录。网关及服务检查签名、会话有效性，Redis会话缓存最长30秒；资金/教师管理操作回源核验。刷新/登出校验Origin与CSRF token，CORS仅两个前端允许源；本地代理保持同源。

登录、注册、已发布商品介绍和健康存活使用公共路由。刷新、退出以专用cookie和CSRF校验鉴权，支付回调以渠道凭据验签，演示媒体以短期播放凭据及实时权益校验鉴权。网关删除客户端身份头；服务自行验JWT，不相信X-User-Id。服务间使用短期HS256服务凭据（独立密钥，aud为目标服务、60秒、操作白名单），携带原用户JWT或可审计actor；内部API不得经公网网关暴露。匿名问答投影屏蔽作者ID，管理员追溯独立权限和审计。

同步默认连接2秒/响应5秒，Feign不自动重试写请求；领域持久命令由协调器重试。HTTP模型超时另见作业文档。所有拒绝访问默认fail closed，不因学习服务宕机开放付费内容。

## 5. 事务、消息与调度

固定使用MySQL事务＋Outbox＋RabbitMQ持久队列＋消费幂等。域写入和outbox同行事务；发送端publisher confirm后标SENT；确认丢失允许重发。消费者domain mutation＋inbox同事务，提交后ack；业务唯一键再次防重，不能只按eventId。

事件封装：eventId(UUID)、type、schemaVersion=1、aggregateId、aggregateVersion、occurredAt(UTC)、traceId、payload。Rabbit topic交换机bc.domain.v1，队列bc.{service}.{event}.v1，每队列独立死信；重试由持久nextRetryAt驱动，禁止requeue热循环。投递延迟序列5秒/30秒/2分钟/10分钟/30分钟，后每30分钟，失败10次进需关注状态仍保留事实；管理员只可重投同事件，不改payload。

扫描每5秒分页100行，用FOR UPDATE SKIP LOCKED领取30秒租约；外部IO事务外执行，结果更新校验leaseToken。数据库时间UTC DATETIME(3)，所有服务本机开发共用数据库时钟基准，生产部署须监测时钟误差；业务顺序以拥有服务提交的序列为准，不由客户端时间或MQ到达顺序判断。

事件/内部命令清单见接口契约；Rabbit不可用仍可保存outbox，UI显示处理中。订单、AI、积分、券另有领域恢复扫描；不能只重投消息而不核对事实。Redis删除后应可从MySQL重建，API正确性不依赖缓存。
