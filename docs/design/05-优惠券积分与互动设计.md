# 优惠券、积分与互动实施设计

日期：2026-11-17；关联ORD-03/04及扩展、PTS、SOC。本文确定算法、事务和恢复；业务定义见需求稿。

## 1. 券模型和时间

coupon_rule不可变版本：type=NO_THRESHOLD/FULL_REDUCTION/DISCOUNT；scope=ALL/COURSE/CATEGORY/ROUTE，targetId按scope必填或空；满减thresholdCent>0，减额>0；无门槛threshold=0；折扣payRateBps在1～9999（9000表示九折），maxDiscountCent>0，可配置门槛>=0。无关参数必须null，不同时配置两套优惠。

activity包含多个activity_item，每项引用规则及库存、个人限额；exchange_project独立配置规则、积分价、库存、限额及时间。积分项目更换规则不改已兑券，只更换以后发券的ruleVersionId。累计兑换数按projectId不重置。规则无人取得时可改，有取得后新增版本；库存/限额/兑换价修改带revision，事务锁与领取互斥。

开放期与使用期均[start,end)，北京时间输入显示，UTC落库；有效N天为N*24小时，N取1～3650整数。用户券取得时固定validFrom/validUntil及规则版本。固定期已结束不可再领，尚未开始可领但不可用；发放时需validUntil>now。领券/兑换同用户同请求幂等，相同来源累计计数包括用掉、过期，取消订单释放不增加计数。

用户券status=AVAILABLE/LOCKED/USED；未生效/过期为AVAILABLE的时间投影，不让定时任务覆盖LOCKED。锁定需当时有效，锁券成功快照沿用至订单截止；退款不退券，关闭释放不改有效期。

## 2. 唯一优惠计算实现

输入：已抵扣后每付费课remainingCent、分类祖先集合、商品routeId、所有候选用户券及不可变规则。路线/全场券覆盖全部剩余付费课，课程券仅指定一门，分类券按下单分类快照匹配所选分类或后代。已拥有和免费课不入基数。

对顺序中的每张券：
1. B=当前覆盖课程remainingCent之和，先判B>0且B>=thresholdCent。
2. NO_THRESHOLD/FULL_REDUCTION期望优惠=amountCent；DISCOUNT期望优惠=floor(B*(10000-payRateBps)/10000)，再min(maxDiscountCent)。
3. D=min(期望优惠,B,全单remainingCent-100)。D<=0则本顺序无效。
4. 用交易文档allocate(D,覆盖课程当前余额)分摊，逐课扣减；全部课程不能负数。记录应用前基数、实际D及分摊。
5. 下一张重新算门槛；每单最多3张，同ACTIVITY/activityId或EXCHANGE/projectId最多一张。

推荐：枚举0～3张所有合法来源组合的全部排列；以总优惠降序、张数升序、将组合内validUntil升序排列后按时间向量字典序决胜，最后按实际使用顺序的券ID数值向量字典序决胜。手选：只枚举所选券全部排列，全部必须有效；无方案返回COUPON_COMBINATION_INVALID，不能丢券。
候选数量不静默截断。相同ruleVersionId＋来源键＋时间适用性相同的券可压缩成有效期最早/ID最小一张（同来源已禁止同单两张，其他计算效果完全相同）；除此之外不做未经证明的剪枝。营销创建pricing_job（quoteId唯一）持久计算任务，500ms未完成返回CALCULATING；交易轮询营销任务并更新自身price_quote，浏览器只查交易报价。超过5秒仅显示“计算中”，不重新创建同一计算；到报价5分钟期限仍未完成则EXPIRED，不返回局部最优。故障用原quoteId恢复，队列租约及结果hash持久化。性能验收100张原始候选，多种范围重叠；规模优化保持与穷举oracle一致。

确定样例：
- 30000分、满20000减5000、满20000打九折上限10000，不同来源：先折扣后满减，优惠8000，实付22000。
- 2000分＋面额2000无门槛：实际优惠1900、实付100，整券消耗。
- A10000/B20000，全场减3000→分摊1000/2000，A剩9000；A满10000减1000此时不生效。先A券再全场可行，系统应找该顺序。
- 折扣基数101分、九折，期望10分，但保底后只优惠1分。
- 同活动的两张即使不同券型也禁止；不同活动同规则允许，受3张及正优惠约束。

## 3. 领取、兑换与锁券事务

活动领取锁activity→activity_item→coupon_rule→acquisition_counter，验证ACTIVE、开放期、issued<stock、个人数<limit；写user_coupon、计数、领取记录同事务。暂停/调库存使用相同锁顺序；首次发券将coupon_rule.issued置true与授券同事务，规则修改也锁同一rule行，避免修改与首领竞态。余额为0不影响免费活动领券。

兑换锁exchange_project→coupon_rule→points_account→acquisition_counter；库存/项目开放/余额/版本价格校验，通过后扣余额、写EXCHANGE流水、加累计数、发券、记exchange_record同事务。用MySQL条件更新保证并发；任一步失败整事务回滚。请求expectedRevision与配置不一致返回EXCHANGE_CHANGED重新确认，不能按新价格静默扣款。兑换不支持主动撤销、不改月榜。

锁券内部接口携带orderId、pricingHash及userCouponIds（<=3），按券ID排序锁行，一次全成或全失败；校验来源、状态、时间、归属及计算快照。重复同订单/同hash返回原结果，不允许同订单换锁另一组。USE只接受本订单LOCKED，RELEASE只接受本订单LOCKED；USED不可释放。核销/释放依据已核实交易状态，不接受浏览器调用。协调UNKNOWN不提前释放。服务故障后扫描订单锁券记录向交易批量查询再补齐，不能仅看券年龄。

## 4. 积分账本

权威MySQL points_account(available,debt,revision)、points_ledger、points_month；Redis只是月榜/签到投影。奖励先校验业务去重，再锁points_account→日额度（仅视频）→points_month，写账本与投影outbox同事务；视频游标锁位于账户锁之前。并发唯一冲突回滚并返回已处理结果。

奖励r：offset=min(debt,r)，available+=r-offset，debt-=offset，月榜+=r；流水记rewardPoints=r、balanceDelta=r-offset、debtDelta=-offset、rankDelta=r。撤回优秀奖励5：取回=min(available,5)，available-=取回，debt+=5-取回；原奖励月榜-=5。撤回唯一键rewardLedgerId＋REVOKE，普通取消优秀不进入撤回。兑换流水rankDelta=0。

每条积分业务键：
- VIDEO: userId/lessonId（永久唯一，即使超日限也写结果0）。
- SIGN: userId/date；连续奖励并入当天一条流水，dayCount和base/bonus单独记录。
- EXCELLENT: noteId（唯一作者由原始笔记事实取值）。
- REVOKE: originalRewardId。
- EXCHANGE: exchangeRequestId。

视频事件只使用学习事务的occurredAt与专用completionEventSequence。营销锁learning_event_cursor→points_account→points_day_quota，按completionEventSequence连续消费，缺口从学习补齐；普通userSequence不用于此游标。日期按Asia/Shanghai业务发生日，日额度不足则写0分流水/SKIPPED_DAILY_CAP，该小节永久不补发。客户端不能指定发生日，跨日迟到仍计原日额度。

积分上线前开发阶段产生的学习事件不视为真实用户奖励承诺：S04就建立积分账本和消费能力，S05才接首次完成奖励，避免后补引发跨日漏算。开发种子可重建，但不改真实业务记录。

签到服务端本日事务唯一记录，从本月已有签到推导连续值，缺一天归1、月初归1。7/14/28天奖励分别加10/20/40，不按7天循环。Redis Bitmap只读投影，丢失从签到表恢复。恶意传date忽略，只认服务端今天。

优秀笔记奖励/撤回乱序：互动输出noteRewardVersion和原奖励eventId，营销先存收件箱；撤回先到则保存pending revoke，待原奖处理后在同一账户锁下撤回，最终净奖励0，不产生负月分或丢撤回；不能先因无流水而丢事件。

## 5. 月榜和历史修正

points_month PK(month,userId)，score>=0、revision；每次积分事务直接改原发生月。签到先锁points_account，再读取/创建当天sign_record并计算连续天数，避免两个首次请求各写一条。当前/历史榜同一权威表查询ORDER BY score DESC,user_id ASC，仅学生且score>0参与。排名为ROW_NUMBER，不并列，分页20～100；我的排名count(高分或同分低ID)+1，无积分显示未上榜。不公开手机号。

Redis ZSet可用score=-points，member=固定20位补零userId，ZRANGE可在同分时按ID升序；不把ID转double。缓存写绝对score并比较revision，不能盲目ZINCRBY重试。月初归档任务只建立月份状态和可重建缓存，不封死历史表；迟到奖励/撤回直接更新对应月、递增revision、重建该月缓存。Redis故障时查MySQL，结果正确优先。

用户角色/昵称通过user.profile-changed.v1维护marketing的student_profile投影，按用户revision拒绝旧消息；初始缺数据用受控批量接口补齐。榜单SQL先过滤当前role=STUDENT再排名，不能先分页后移除教师/管理员而导致名次和总数错误。角色变化清除该用户各月缓存投影，历史积分账本保留。

## 6. 互动内容与治理

question绑定course/lesson?，学生有权益可提问，标题1～100、正文1～10000，anonymous可设；answer绑定question，comment绑定answer，正文1～10000。可编辑/逻辑删除本人内容；教师负责课程可答，管理员隐藏违规内容必须reason。删除问题逻辑墓碑使整线程不可公开访问，不物理删回答/评论，管理员审计可查；恢复不作为首版用户功能。匿名投影使用“匿名学员”，不返回可反查作者ID，管理员追溯独立接口留审计。不做AI回复、采纳和悬赏。

note绑定course/lesson/positionMs，正文<=20000；visibility=PRIVATE/COURSE_PUBLIC，type=ORIGINAL/COLLECTED。采集时保存原作者显示快照与正文、sourceNoteId；unique(owner,sourceNoteId)，不可采自己、不可改为公开。原文更新不覆盖副本，删除原文不删除副本；副本再次采集不开放。笔记课程/小节删除后显示“原课程/小节已下架”，本人仍可管理，不能借旧媒体ID播放。退款后本人管理仍可，但无权益不能新增该课程笔记/采集别人内容。

优秀评选锁note行，只能负责课程公开原创、未隐藏；固定note_revision，插入excellent_reward（noteId唯一）、outbox；作者修改内容或改私密自动取消优秀显示，不再发奖。普通取消不扣分；管理员违规撤回写reason并产生REVOKE。点赞仅answer/comment，unique(user,type,target)，不能自赞；取消幂等，数量在同事务按active变化增减，Redis缓存可重建。

## 7. 验收

券算法以小候选集全排列oracle对照；边界100分、尾差、分类调整快照、重叠范围、同来源限制、过期锁券继续支付均覆盖。100并发抢10券只成功10；兑换失败不扣分不发券，重试一次仍只有一个结果。

积分并发6个首次完成仅50分；次日重看不得补；签到跨月重置；兑换不减榜；债务3再获10→余额+7/月榜+10；优秀5已兑换后撤回→债务5、原月-5、券保留；撤回先于奖励、跨月迟到和Redis清空重建均验收。

互动验收越权、匿名不泄露、删除线程墓碑、采集不可公开/重复、退款后个人笔记可管理、改优秀笔记自动取消展示不重奖，所有正常互动不得额外加积分。
