## 2. 常用排障命令

```powershell
powershell -ExecutionPolicy Bypass -File scripts\check-deps.ps1
powershell -ExecutionPolicy Bypass -File scripts\start-local.ps1
powershell -ExecutionPolicy Bypass -File scripts\stop-local.ps1
```

- 健康检查：`http://127.0.0.1:18080/actuator/health`、18081～18087 各自 `/actuator/health`。
- 日志：`.local-run/logs/<service>.out.log`、`.err.log`；先看 `ERROR`、首个 `Caused by` 和 traceId。
- PID：`.local-run/pids.json`；停止只杀自己记录的 PID，不按端口盲杀。
- 数据库连接：`MYSQL_PWD=1234 mysql -h127.0.0.1 -uroot -e "SHOW DATABASES"`（密码来自本机配置，不提交）。
- Rabbit：`scripts/start-rabbit.ps1` / `stop-rabbit.ps1`；vhost `/job-bootcamp-dev`。
- Redis：`scripts/start-redis.ps1` / `stop-redis.ps1`；投影 key 前缀 `bc:dev:`。

## 3. 常见故障

| 现象 | 优先检查 | 处理 |
|---|---|---|
| 启动提示端口被占用 | `.local-run/pid.json`、`Get-NetTCPConnection` | 先 `stop-local.ps1`；不要直接杀未知进程 |
| 服务 health DOWN | `*.err.log` 首个异常 | 常见是 MySQL 未启动、库不存在、密码/端口错误 |
| Flyway 校验失败 | 是否手工改过已执行迁移 | 不修改历史迁移；本地演示库可用 `reset-demo-db.ps1 -Confirm` 重建 |
| 401 | access token 过期、refresh cookie 丢失、clientApp 不一致 | 重新登录；检查网关/用户服务会话 |
| 403 | 角色、教师范围、课程/路线权益 | 用 S16-a 权限矩阵定位；不要靠前端隐藏绕过 |
| 404 | 资源不存在，或隐藏/删除/不可见 | 管理员内容治理使用独立接口；不要向普通读取接口探测私人数据 |
| 409 | 版本冲突、库存/限兑、重复撤回、订单重叠 | 刷新最新 revision/余额后重试；不要自动重放写请求 |
| 422 | 业务校验（积分不足、券组合不可行） | 展示具体业务错误，不按 500 处理 |
| 购买后订单 PAID 但未开通 | 学习服务、Rabbit outbox、trade 事件 | 先恢复 learning/Rabbit，再查 trade order fulfillment 与 learning source |
| 积分未到账 | Rabbit、营销 inbox、日限额/债务 | 查 `trade/learning outbox`、`inbox_event`、`points_ledger`；不要直接改余额 |
| AI 一直 QUEUED | assignment worker、租约、MQ | 查 `ai_task` lease/next_retry；等待租约恢复，不手工改任务成功 |
| 月榜与预期不一致 | Redis 投影、归档月 | 删对应 `bc:dev:` key 或调用重建；MySQL `points_month` 才是权威 |
| 演示数据重复 | 种子固定名称/幂等键 | `seed-demo.mjs` 可重复；完整旅程每次创建新学生 |
| 需要全新演示 | 本地演示库 | `reset-demo-db.ps1 -DryRun` 预览，确认后 `-Confirm`；生产禁止 |

## 4. 关键技术讲解

### 4.1 八服务与数据所有权

每个服务只连自己的库：user/course/learning/trade/assignment/interaction/marketing 各自独占 schema，gateway 无库。跨服务读取走内部 HMAC 接口，写流程靠事件和本地事务；禁止跨库 join/事务。这样能分别扩容、降级和定位故障，但也要求处理最终一致、幂等和补偿。

### 4.2 认证与权限

- 登录返回短期 RS256 access token，refresh 随机哈希存库、HttpOnly cookie、轮换与重放撤销。
- 网关只做入口检查，业务服务仍验 JWT/session；内部接口用短时 HMAC 服务凭据，不暴露 `/int/v1/**`。
- 单角色 STUDENT/TEACHER/ADMIN；教师范围、课程权益、路线福利分别校验，前端菜单不是权限。
- 管理员不是私人数据通行证；匿名问答、私人笔记、教师只读作答均有独立边界。

### 4.3 金额与权益

- 金额只用整数分，BigInteger 做比例分摊和尾差；最低实付 1 元、付费课最低 9.9 元、路线分摊至少 1 元。
- 权益不是布尔值：`entitlement_source` 记录来源（FREE/COURSE_ORDER/ROUTE_ORDER/ROUTE_GRANT 等），撤销/冻结按来源 lifecycle 处理；其他有效来源仍可访问。
- 路线 epoch 固定成员与已购时间：移除课程只关闭 epoch，不撤销已有 grant；新增课程按新 epoch 补发，老学员资格与退款判断都依赖 epoch 快照。

### 4.4 优惠券定价

- AUTO 穷举 0～3 张券的所有合法来源组合与顺序，按总优惠、张数、有效期、券 ID 决胜；手选只排列所选券。
- 逐券先判断当前剩余基数、门槛、范围，再计算优惠并分摊；同活动/同兑换项目互斥，最低实付截断。
- 超过 500ms 创建持久 pricing job，交易轮询；租约与结果 hash 支持恢复。性能测试 100 候选 p95 约 1.6s（本机单实例），没有为速度牺牲最优组合。

### 4.5 可靠事件与 Outbox/Inbox

- 业务写入与 outbox 同事务；relay 用 `SKIP LOCKED` 领取、发送确认、退避重试，失败不丢事件。
- 消费端 inbox 与领域写入同事务，`eventId`/业务唯一键双重幂等；100 相同事件并发时应用按 `consumer+eventId` 串行并重试死锁。
- 发送/消费都不依赖 MQ 到达顺序；订单、积分、AI、券另有事实核对和恢复扫描。

### 4.6 AI worker

- 每次代码提交最多一个逻辑任务；worker 用数据库租约 90 秒、定期续租、leaseToken fencing。
- 10 分钟总期限、6 次调用预算；Qwen 不可请求才切 DeepSeek；格式错误只修同供应商一次，400 不重试。
- 外部调用在事务外，失败/租约过期释放 slot；学生端只读状态，不能选模型或手动重试。

### 4.7 积分与月榜

- `points_ledger` 是资金式账本，`points_account` 余额/债务，`points_month` 月榜；三者同事务。
- 业务键按 VIDEO/SIGN/EXCELLENT/REVOKE/EXCHANGE 类型唯一；债务先抵扣新奖励，但全额奖励仍进对应月榜。
- 兑换只扣可用余额、rankDelta=0；优秀撤回扣回 min(可用,5)，不足记债务，原获奖月份修正。

### 4.8 互动与治理

- 匿名问题投影为“匿名学员”，不返回 authorId；教师默认不能追溯，管理员需独立权限和 reason 审计。
- 笔记采集是私人快照，唯一 `(owner,source)`；原文修改/删除不覆盖副本，退款后本人仍可管理。
- 点赞唯一记录 active 复用；评优锁定内容版本，奖励事实唯一；作者修改取消展示但不退积分，违规撤回走管理员审计和 REVOKE。

## 5. 两分钟项目讲解

> 这是一个八服务的 Java 求职训练营：课程、路线、权益、交易、作业 AI、互动、营销各自独立库，网关统一认证。核心不是 CRUD，而是交易和权益的一致性：价格用整数分和分摊快照，支付/退款通过 outbox/inbox 驱动学习权和积分；券做 0～3 张的全局最优；AI 任务用租约和 fencing 防重复；积分是账本+债务+月榜三表。前端学生/管理端随阶段交付，测试覆盖 mock 支付、退款、AI、故障恢复和 100 并发。真实云媒体、商户支付和模型账号没有凭据，明确标 NOT_RUN。

## 6. 面试追问练习

1. **问：为什么拆八个服务？**  
   按业务所有权拆，避免共享库；每个服务可独立部署、降级和排障。追问“是否过度设计”：本地项目刻意练习边界与一致性，服务粒度按数据所有权而不是按表拆。

2. **问：支付成功但学习服务挂了怎么办？**  
   支付和发权是两个事实；trade 先落 PAID + outbox，learning 恢复后消费并回传 fulfillment。订单不会假装 DONE，学生最终拿到权益。追问：重复回调？inbox eventId + 业务唯一键幂等。

3. **问：为什么用 outbox 不直接 RPC？**  
   RPC 失败会留下跨库半成功；outbox 与业务同事务，relay 可重试，消费者 inbox 幂等。追问：消息重复/乱序？业务键、版本、恢复扫描和事实核对。

4. **问：券怎么保证最优？**  
   0～3 张的所有合法来源组合和顺序穷举；逐券重新算门槛和剩余基数。100 候选也不静默截断。追问：性能？500ms 异步 job，本机 100 候选 p95 约 1.6s，记录真实值不冒充生产。

5. **问：券和积分的边界？**  
   下单锁券、支付核销、取消/到期释放；券过期/退款不退券。积分兑换只扣余额、不影响月榜；兑换券来源为 EXCHANGE。

6. **问：权益退款为什么不能只看订单金额？**  
   权益来源可能被路线抵扣、被其他来源覆盖；退款按来源冻结/撤销，其他有效来源保留，抵扣依赖要释放。追问：历史路线成员？epoch 快照和 grant_route_member。

7. **问：AI 任务怎么防重复和超时？**  
   提交固定版本，单学生单 active task；worker `SKIP LOCKED` 领取、90 秒租约续租、leaseToken fencing、10 分钟 deadline、6 次预算。追问：租约过期？新 worker 恢复，旧 worker 写结果被 token 拒绝。

8. **问：为什么积分要账本+账户+月榜？**  
   账本审计/幂等，账户可用/债务，月榜按业务月；同事务更新，兑换 rankDelta=0。追问：延迟消息跨月？使用学习业务 occurredAt，不按消费时间。

9. **问：点赞为什么先锁目标行？**  
   记录唯一和计数要在同一临界区；锁回答/评论行串行，再更新 like_record 与 count，避免重复赞和丢计数；取消幂等。

10. **问：管理员为何不能直接读私人笔记？**  
    权限按最小范围：治理只查公开原创内容，匿名追溯/隐藏需独立权限和 reason 审计；管理员不是通用私人数据读取者。

11. **问：100 并发积分事件发现过什么问题？**  
    同一 inbox 唯一索引并发插入触发 MySQL 死锁，部分请求 500/30s；修复为同 JVM eventId 串行 + 有界死锁重试，唯一键仍是跨实例权威。追问：为什么不是简单吞异常？吞掉会丢业务处理。

12. **问：100 兑换如何保证不超卖？**  
    项目行锁串行库存/限兑，账户锁扣分，库存+1、计数、发券、记录同事务；100 请求只 10 成功，90 返回 STOCK_EXHAUSTED。

13. **问：为什么不用 Redis 做锁？**  
    Redis 只做可重建投影/缓存；资金和权益正确性依赖 MySQL 行锁、唯一键和事务，避免缓存失效/分区导致超卖。

14. **问：怎么证明不是只做了静态页面？**  
    每阶段都有 API/UI 验收脚本、真实 DB/Rabbit/Redis 证据、失败回滚/并发/越权测试；S17-b 一条脚本走通完整链路。

15. **问：项目最大的限制？**  
    真实 VOD/支付/退款/模型账号未验证，移动端/无障碍未测，多实例/集群未压测；这些明确 NOT_RUN，不用 mock 结果冒充真实联调。

## 7. 演示顺序建议

1. `start-rabbit.ps1`、`start-redis.ps1`、`start-local.ps1`。
2. `node scripts/seed-demo.mjs`，打开学生/管理端看演示数据。
3. `node scripts/demo-journey.mjs`，按输出账号登录学生端复看课程、订单、积分、券、兑换和退款。
4. 管理端看教师评优/治理、活动券、兑换项目、退款对账。
5. 需要讲故障时运行 `s16b-fault-recovery.mjs`；讲并发时运行 `s16c-concurrency.mjs`。
