## S02-a 账号、会话与刷新

日期：2026-11-19（Asia/Shanghai）

## 交付内容

- 新模块 `bootcamp-user`，端口 18081，独占数据库 `bc_user`。
- Flyway：
  - `V1__init_user.sql`：`user_account`、`role_permission`、`auth_session`、`refresh_history`。
  - `V2__ascii_token_hashes.sql`：`refresh_hash`、`csrf_hash`、`used_hash` 改为 `ascii/ascii_bin`。
- 演示种子（应用启动时执行，不写入正式迁移）：student01～03、teacher01～02、admin01，默认密码来自 `DEMO_PASSWORD`（缺省 `Demo@123456`）；管理员 10 个权限码。
- 接口：
  - `POST /api/v1/auth/register`、`/login`、`/refresh`、`/logout`
  - `GET/PATCH /api/v1/me`、`PUT /api/v1/me/password`
- 安全实现：
  - Access JWT RS256，15 分钟，claims 包含 sub、role、sessionId、tokenVersion、iss、aud、exp、jti。
  - Refresh 为 32 字节随机值，SHA-256 存库，7 天；每次刷新轮换，旧值写 `refresh_history`。
  - 旧 refresh 重放：撤销该用户全部会话、递增 tokenVersion，旧 access 也立即失效。
  - CSRF cookie 可被 JS 读取，refresh/logout 必须带 `X-CSRF-Token`；refresh cookie HttpOnly，Path=/api/v1/auth。
  - 密码 BCrypt；注册只创建 STUDENT；登录时 `X-Client-App`/`clientApp` 校验角色范围。
  - `/api/v1/me` 由服务端校验 JWT 签名、会话状态、用户启用状态与 tokenVersion；不以信任身份头代替。
- 本地 key：开发模式在 `.local-run/jwt` 自动生成 RSA 2048 密钥（已忽略，不入库）；生产必须用 `JWT_PRIVATE_KEY_PATH`/`JWT_PUBLIC_KEY_PATH` 提供并关闭生成。

## 过程中发现并处理

## S02-b 网关、服务凭据与账号管理

日期：2026-11-19（Asia/Shanghai）

## 范围

需求依据 AUTH-01/04 与任务书 S02-b：Gateway 路由、服务端资源 JWT 校验、内部凭据、白名单/CORS/CSRF、教师和管理员账号管理。

## 交付内容

- 新模块 `bootcamp-contracts`（无 Spring 依赖）：`InternalTokenCodec`（HMAC-SHA256 服务凭据，60 秒、audience + operation 白名单）、`SessionCheckResponse`。
- 新模块 `bootcamp-gateway`（18080，Spring Cloud Gateway `server-webflux` 5.0.4）：
  - 静态路由：`/api/v1/auth/**`、`/api/v1/me`、`/api/v1/admin/**` → user；`/api/v1/categories`、`/api/v1/courses`、`/api/v1/routes` → course。
  - 公共白名单：登录/注册/刷新/退出、已发布课程与分类、健康；其余 `/api/v1/**` 需要 access token。
  - 受保护请求先调用 user 内部 `/int/v1/sessions/check` 校验会话；认证服务不可用时 fail closed 返回 503。
  - 删除客户端提供的 `X-User-Id`、`X-User-Role`、`X-User-Name`、`X-Session-Id`、`X-Service-Token`；不向下游注入身份头。
  - `/int/v1/**` 不暴露，返回 404；错误体使用统一 `code/message/data/traceId`，响应带 `X-Trace-Id`。
  - CORS 仅允许 `http://localhost:15173`、`http://localhost:15174`，允许 Authorization、Content-Type、X-CSRF-Token、X-Client-App。
- user 服务：
  - `SessionValidator` 复用 JWT/会话/用户/tokenVersion 校验。
  - `POST /int/v1/sessions/check`，由 `InternalAuthInterceptor` 校验服务凭据（aud=bootcamp-user，operation=sessions:check）。
  - 管理员账号管理：`GET/POST /api/v1/admin/users`、`PATCH /api/v1/admin/users/{id}`；需要 ADMIN 角色 + `user:manage` 权限。
  - 管理员可创建教师/管理员账号；不能通过管理接口创建学生；禁用或更改角色会递增 tokenVersion 并撤销该用户全部会话；禁止管理员禁用自己或修改自己的角色。
  - 分页使用 MyBatis-Plus `PaginationInnerInterceptor`。
- 配置：`INTERNAL_TOKEN_KEY` 本地缺省为 dev 占位值；生产必须用环境变量注入。当前使用静态路由，Nacos 与 Redis 未接入。

## 过程中发现并修复

- Boot 4 的 WebFlux starter 不提供 `WebClient.Builder` 自动配置，改为直接 `WebClient.builder()`。
- Gateway 5 的配置前缀是 `spring.cloud.gateway.server.webflux.*`，旧前缀不会加载路由。
- 过滤器中 `switchIfEmpty` 挂在整条 `flatMap` 链后，响应已转发成功时也会被当作空结果写 503；改为在会话检查 Mono 上用 `Optional` 显式表达“无结果”，避免在响应已提交后写错误。
- 验收脚本最初用学生端 clientApp 登录教师账号，返回 403 是正确行为；脚本改为使用管理端 clientApp。

## S02-c 登录页、角色菜单与续会话

日期：2026-11-19（Asia/Shanghai）

## 范围

需求依据 AUTH-01/04 与任务书 S02-c：登录页、个人资料页、按角色菜单、403/过期登录返回路径。S02 阶段的“刷新页面/多标签页续会话”在本任务实现并验证。

## 交付内容

学生端：

- `/login`、`/register`、`/me`（个人资料）、`/forbidden` 页面；首页保留服务状态并显示当前登录身份。
- `AppShell` 按学生角色生成菜单，显示昵称、角色和退出。
- 会话层：
  - Access token 只保存在页面内存；
  - 刷新页面时读取可被 JS 读取的 CSRF cookie，带 `X-Client-App: STUDENT` 调用 `/api/v1/auth/refresh`，用 HttpOnly refresh cookie 续期；
  - 使用 Web Locks 串行刷新，BroadcastChannel 在同源标签页之间同步登录/退出/新 access token；
  - Axios 遇到 401 时只重试一次，先刷新；刷新失败清除本地状态并跳登录。
- 路由守卫：未登录访问受保护页面时记录 `redirect`，登录后回到原页面；角色不匹配进入 403 页面。
- 个人资料：昵称/头像地址（暂不做上传）按 revision 更新；改密后清除会话并重新登录。

管理端：

- `/login`、`/`、`/admin/users`、`/teacher`、`/me`、`/forbidden`。
- 管理员菜单：首页、账号管理、个人资料；教师菜单：首页、教师工作区、个人资料；教师访问 `/admin/users` 被路由守卫送到 403。
- 账号管理页接 S02-b 的接口：列表/搜索/分页、创建教师或管理员、启停账号、修改角色；禁用或改角色后旧会话失效。
- 教师工作区当前只显示阶段说明，不伪造业务功能。

前端代理：两个应用的 `/api` 指向网关 18080；`/actuator` 仍指向课程服务 18082，用于首页健康展示。
