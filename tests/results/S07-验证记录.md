## S07-a 路线报价、购买预留与抵扣边（2026-11-21）

### 1. 需求与实现范围

- 需求：BUY-01/02/03/03A/03B/04/05/08、ORD-02A、BEN-03～06 的路线购买前置部分。
- 新增/扩展表：
  - learning `V3 purchase_hold`：PREPARED/COMMITTED/RELEASED，唯一 `(order_id, course_id)`。
  - trade `V4 deduction_link`：RESERVED/COMMITTED/RELEASED，唯一 `(dependent_order_id, course_id)`。
  - trade `V5`：允许路线订单中被抵扣/免费课程的单课实付为 0，整单最低实付仍由 `trade_order` 校验。
- learning 内部接口：
  - `POST /int/v1/entitlements/sources`
  - `POST /int/v1/purchases/prepare`
  - `POST /int/v1/purchases/commit`
  - `POST /int/v1/purchases/release`
- 课程内部接口：`POST /int/v1/routes/snapshots`。
- trade：`productType=ROUTE` 的报价/订单；路线支付在 S07-a 明确拒绝，等待 S07-b。

### 2. 关键实现

1. 路线快照由课程服务按当前路线版本成员生成，包含课程版本、epoch、单课价格、套餐分摊、分类祖先、活动小节和媒体时长；只对新购付费课检查可播放视频。
2. learning 按 `course_grant.granted_at, grant.id` 升序选每门课最早 ACTIVE 来源；同一来源可被多个依赖订单使用，不因预留换选新来源。
3. 报价已拥有课程按套餐分摊价值抵扣；免费成员分摊 0；未拥有付费课按分摊价计入应付。全部付费成员已拥有时不创建零元订单，返回 `ALREADY_OWNED`。
4. 订单创建重新读取路线快照和来源，重算 quoteHash；变化返回 `QUOTE_CHANGED` 并把报价标记为 STALE。
5. 路线订单写 `order_course` 全部成员（已有课 credit=allocated、payable=0；新付费课 credit=0、payable=allocated），只为本次新购付费课写 `order_lesson`/`pending_course`。
6. 对已有课程写 `deduction_link`（sourceOrderId 可为空，例如 FREE 来源），并在 learning 建立 `purchase_hold`；取消/订单关闭释放 PREPARED hold 和 RESERVED link。
7. `order.snapshot` 固化路线版本、成员分摊、抵扣来源和 quoteHash；`snapshot_hash` 使用路线快照 canonical hash。
8. 路线订单支付入口在 S07-a 返回 CONFLICT，避免 S06 的单课发权逻辑错误处理路线。

### 6. 理解问题与精简回答

1. **为什么路线已拥有课程只抵扣、不新增路线来源？** 已有课程保留原来源，路线订单只为本单新获得的付费课建立路线来源；否则同一课程会因抵扣产生重复权益，也会让退款基准变乱。
2. **为什么选目标课程 grant 的最早时间，而不是来源 acquiredAt？** 1 日买路线、3 日单买 C、5 日路线才新增 C 时，课程 C 在 3 日已经通过单课获得，抵扣必须选 3 日来源；用路线 acquiredAt 会错选 1 日路线。
3. **为什么全部已有不能创建零元订单？** 零元订单会制造虚假的支付/路线资格事实；BUY-04 要求直接按推荐顺序学习，不为路线新增福利或未来课程资格。
4. **为什么需要 purchase_hold 和 deduction_link 两张表？** hold 是学习侧的来源预留，link 是交易侧订单依赖关系；支付前要能分别释放/提交，支付后才能保留依赖用于退款链校验。

## S07-b 路线支付、未来课程与福利资格（2026-11-21）

### 1. 需求与实现范围

- 需求：BUY-01A、BUY-03B、BUY-06、BUY-07、ORD-02A、BEN-03～06。
- 新增 learning 表：`grant_route_member`、`route_epoch_projection`。
- 扩展事件：`trade.payment-confirmed.v1` 现在携带 `productType`；路线事件包含 `routeId` 和成员 `courseId/courseVersion/epochId/free/newPaid`。
- 学习新增：`RouteChangedListener` 消费 `course.route-changed.v1`；`EntitlementService.grantRoutePurchase/applyRouteChange`。
- 路线支付不再被 S07-a 的临时保护拦截，允许 MOCK 支付。

### 2. 关键实现

1. 路线支付有效时，trade 先调用 learning `purchases/commit` 提交 source hold，再把 `deduction_link` 从 RESERVED 置为 COMMITTED，最后把订单置 PAID 并写 `trade.payment-confirmed.v1`。
2. learning 消费路线支付事件：
   - 建立 `ROUTE_ORDER` 来源和 `route_entitlement(future_courses=true)`；
   - 本次新购付费课在路线来源下建立 grant；
   - 免费成员建立独立 `FREE` 来源和 grant，路线退款不撤销；
   - 已抵扣课程不新增路线 grant；
   - 所有当前成员写 `grant_route_member(sourceId,epochId,courseId,paidAt)`。
3. 路线成员新增事件 `course.route-changed.v1`：
   - 更新 `route_epoch_projection`；
   - 对已有 ACTIVE 路线资格用户补发新增付费课/免费课，grantedAt 使用 epoch 的 `joinedAt`，不早于此前单课 grant；
   - 已移除 epoch 只关闭投影，不撤销已有课程 grant。
4. 路线付款回执通过 `learning.order-granted.v1` 回填新购付费课来源；trade 的 fulfillment 只统计 `is_new_paid=TRUE` 的 order_course，免费/抵扣课不阻塞 DONE。
5. 路线支付失败/过期时释放 route hold 和 RESERVED deduction_link。

### 5. 理解问题与精简回答

1. **路线支付后为什么已抵扣课程没有新的路线 grant？** 它保留原来源即可继续学习；路线 grant 只给本次新购课程，避免重复权益和退款基准重复计算。
2. **免费成员为什么用 FREE 来源而不是 ROUTE_ORDER？** 免费课程的领取事实独立于路线购买，路线退款不能撤销它；后续仍可按免费领取规则展示。
3. **新增课程为什么用 joinedAt 作为 grantedAt？** 这样先单买 C 的用户保留更早的单课 grant；后加入路线的人也不会把新课程倒签到路线购买时间。
4. **移除课程为什么只关闭 epoch、不删 grant？** 历史购买者已获得课程权益，BUY-07 要求移除只停止新销售；福利题历史访问由旧 epoch 继续判断。

### 4. 理解问题与精简回答

1. **为什么确认页不自己计算抵扣？** 抵扣来源、分摊和金额必须由服务端快照决定；前端只格式化服务端报价，避免改价或来源变化时显示错误金额。
2. **为什么退款依赖提示要放在确认前？** 用户需要知道某个已有课程来源订单可能被退款影响；正式退款判定仍以受理时点的快照和依赖边为准。
3. **为什么“我的路线”与“我的课程”分开？** 路线资格本身包含未来新增课程和福利资格，不能只用一个课程来源列表表达。
