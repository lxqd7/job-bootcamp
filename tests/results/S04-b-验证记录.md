## 交付内容

- Flyway V2：
  - `sign_record`：用户/业务日唯一，记录连续天数、基础分、奖励分、发生时间。
  - `student_profile`：用户昵称、角色、用户 revision 投影，供月榜过滤学生和展示昵称。
- 签到：
  - 只认服务端北京时间今天，客户端不能指定日期。
  - 同日唯一记录；100 个并发请求只产生一次签到和一条积分流水。
  - 连续天数从本月已有记录推导；缺一天归 1，月初归 1，跨月不沿用上月连续天数。
  - 第 7/14/28 天分别奖励 10/20/40，当天合计 11/21/41；不为其他天数重复发放。
  - 签到积分走统一积分账本，参与债务抵扣和月分累计，业务键 `userId:date` 唯一。
- 月榜：
  - MySQL `points_month` 为权威数据；只统计 `score > 0` 的学生。
  - `ROW_NUMBER() OVER (ORDER BY score DESC, user_id ASC)`，同分按用户 ID 升序，不并列。
  - 分页 20～100；返回昵称、积分、排名、总数和我的排名。
  - 当前/历史月份统一按 `YYYY-MM` 查询，历史榜不封死。
- 学生资料投影：
  - 用户服务新增内部批量接口 `POST /int/v1/profiles/batch`，最多 100 个用户，使用 `profiles:batch` 服务凭据。
  - 营销服务在查询月榜时批量同步参与者资料；用户服务不可用时降级为 `学员{userId}`，不阻断月榜主流程。
- Redis：
  - 月榜：ZSet `bc:dev:board:{month}:rank`，score 为负积分，member 为 20 位补零 userId；同分按 member 字典序即 ID 升序；names hash 和 revision 元数据。
  - 签到：Bitmap `bc:dev:sign:{userId}:{month}`，按日偏移；丢失后从 `sign_record` 重建。
  - 缓存按 `SUM(points_month.revision)` 判断新鲜度；积分变化后自动重建。
  - Redis 故障或删除 key 时回退 MySQL，结果正确优先。
- 签到接口：`POST /api/v1/sign-ins`（签到）、`GET /api/v1/sign-ins?month=YYYY-MM`（本月签到日与连续天数）。
- 月榜接口：`GET /api/v1/boards/monthly?month=YYYY-MM&page=1&pageSize=20`。
- 测试夹具（仅 `POINTS_TEST_API_ENABLED=true`）：
  - `POST /dev/points/fixtures/sign`
  - `POST /dev/points/fixtures/sign-days`
  - `POST /dev/points/fixtures/month-score`
  - `POST /dev/signs/{userId}/cache/rebuild`
  - `POST /dev/boards/{month}/rebuild`

## 过程中发现并处理

- 月榜缓存最初用 `MAX(revision)` 判断新鲜度，低 revision 用户变化时可能误判；改为 `SUM(revision)`。
- 用户资料批量接口原本没有内部操作码，新增 `profiles:batch` 并按路径选择校验 operation。
- 月榜昵称依赖用户资料；先同步参与者再查询，避免先分页后过滤角色导致名次错误。
- 测试夹具 seeded 的 28 天连续记录跨月，只用于验证奖励计算；真实签到在月初仍会重置连续天数。
