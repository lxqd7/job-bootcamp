## S10-a 正式作业草稿与不可变版本（2026-11-23）

### 1. 需求与实现范围

- 需求：HW-01B、HW-02、HW-02A、HW-04、HW-05。
- 新增 assignment 服务：管理员维护每章一份章节选择题、每门课程一份课程代码题。
- 草稿可反复修改；发布时生成递增版本号的不可变 `assignment_version`；已发布内容修改后再次发布生成新版本。
- 下架只改 `status=OFFLINE`，保留当前版本和历史；未发布不接入课程购买/播放，不阻止学习。
- 学生作答、判分、attempt、草稿、参考实现解锁和 mock AI 属 S10-b；学生页面/教师只读属 S10-c。

### 2. 服务、数据与接口

新增：

- `backend/bootcamp-assignment`，端口 18085，数据库 `bc_assignment`。
- `assignment(id,kind,course_id,chapter_id,author_id,status,current_version_id,draft_json,revision,formal_scope_key)`：
  - kind=CHAPTER_CHOICE/COURSE_CODE；
  - `formal_scope_key` 唯一：`CHAPTER:{id}` 或 `COURSE:{id}`。
- `assignment_version(assignment_id,version_no,public_body,answer_body,published_at,prompt_version)`，`(assignment_id,version_no)` 唯一且发布后不变。
- `assignment_route` 预留福利题路线 epoch 绑定。
- 内部模块：MyBatis 分页、用户会话校验、ADMIN 权限校验。
- 管理员 API：
  - `GET/POST /api/v1/admin/assignments`
  - `GET/PATCH/DELETE /api/v1/admin/assignments/{id}`
  - `POST /api/v1/admin/assignments/{id}/publish|offline`
- 网关新增 assignment 路由；启停脚本/check-deps 增加 assignment 进程、端口和数据库。

### 3. 关键实现

1. 创建时按 kind 生成唯一 scope key，同一章节/课程不能重复配置正式作业。
2. 章节选择题校验 1～50 题、单选/多选、2～8 个唯一选项、答案组合、分值和解析；多选至少两个正确选项，单选最多一个。
3. 代码题校验场景、要求、slot 数量、初始代码、参考实现 slot 集合、rubric 和总长度。
4. 发布在 assignment 行锁内读取 `max(version_no)+1`，把 public/answer 分开写入版本快照；草稿修改不会改动旧版本。
5. 下架保留 currentVersionId 和历史版本；已发布作业不能物理删除，只能下架。
6. 管理端使用 JSON 编辑器填写公开题面和标准答案，提供章节选择题/课程代码题示例，并显示当前发布版本。

### 6. 理解问题与精简回答

1. **为什么草稿和发布版本分开？** 草稿可以反复修改，版本是学生作答和历史提交唯一可引用的不可变快照；修改答案不能让旧作答被重新解释。
2. **为什么同一章节/课程用 formal_scope_key 唯一？** 这是“每章一份、每课一份”的数据库级约束，避免两个管理员并发创建两份正式作业。
3. **为什么下架不删除版本？** 旧 attempt 和历史提交仍需引用题目、答案和解析；下架只阻止新作答（S10-b）。
## S10-b Attempt、版本判分、草稿与 mock 点评（2026-11-23）

### 1. 需求与实现范围

- 需求：HW-01、HW-01A、HW-01B、HW-02、HW-02A、HW-03、HW-04、HW-05。
- 开始 attempt 时固定 assignment currentVersion；提交时只按 attempt.versionId 判分；历史提交绑定版本。
- 草稿可跨设备保存，revision 冲突返回 409 且不覆盖另一端内容；保存草稿不创建 submission，也不占 AI 名额。
- 选择题按固定版本答案判分；代码题创建 mock 异步点评任务，复用正式 `ai_task/ai_user_slot/ai_feedback` 表，单学生同时一个任务。
- S10-c 学生页面/教师只读记录未做；S11 真实 AI 与租约恢复未做。

### 2. 数据与接口

新增 assignment V2：

- `attempt(id,user_id,assignment_id,version_id,started_at,status,draft_json,draft_revision)`。
- `submission(... version_id,attempt_id,answers_json,score,max_score,review_state,request_key,request_hash)`，attempt 唯一、请求键唯一。
- `ai_user_slot(user_id PK, active_task_id)`；`ai_task` 状态 QUEUED/RUNNING/RETRY_WAIT/SUCCEEDED/FAILED 和 deadline/lease 字段；`ai_feedback` mock 结果。

学生接口：

- `GET /api/v1/courses/{courseId}/assignments`
- `GET /api/v1/assignments/{id}`（不含标准答案）
- `POST /api/v1/assignments/{id}/attempts`
- `GET /api/v1/attempts/{id}`
- `PUT /api/v1/attempts/{id}/draft`（draftRevision）
- `POST /api/v1/attempts/{id}/submissions`（必须 Idempotency-Key）
- `GET /api/v1/assignments/{id}/submissions`
- `GET /api/v1/submissions/{id}`、`/review`

本地 mock 触发：`POST /api/v1/dev/assignments/mock-review`（ADMIN，mock 开启时注册）；默认 worker 每 800ms 扫描，验收时用 `AI_MOCK_POLL_MS=600000` 加显式触发，稳定验证单任务约束。

### 3. 关键实现

1. 开始 attempt 读取 currentVersionId 并保存；后续 assignment 更新/下架不改变 attempt.versionId。提交只接受 assignment 当前 status=ONLINE，防止下架后新提交；旧 attempt 仍用旧版本答案。
2. 草稿只保存 answers JSON 和 draft_revision；旧 revision 更新返回 409，原草稿保留。
3. 选择题按题目集合完全相等判分；未作答/错误 0 分，多选少选/多选均 0，单选题提交多个选项返回 422。
4. 提交请求用 `(user,attempt,request_key)` 唯一；同一 key + 相同内容返回原 submission，同 key 不同内容/重复提交 attempt 409。
5. 代码题提交先锁 `ai_user_slot`，有 active_task_id 返回 `AI_REVIEW_BUSY`；同一事务写 submission、attempt SUBMITTED、ai_task QUEUED 并占 slot；draft 不占 slot。
6. mock worker 生成 `isMock=true` 的结构化反馈并释放 slot；S11 可替换 worker，不改提交事实表。

### 6. 理解问题与精简回答

1. **为什么 attempt 要绑定 versionId？** 用户开始作答时的题目就是历史事实；题目更新后不能让旧 attempt 用新答案/新分值重算。
2. **为什么草稿不占 AI 名额？** 草稿只是输入，不是提交；只有提交后生成点评任务并占用单学生名额，避免用户边写边锁住名额。
3. **为什么提交必须幂等键？** 提交会产生 submission 和 AI 任务；网络重试不能重复判分或重复扣名额，同键相同内容必须返回原结果。

新增/调整接口：

- `GET /api/v1/assignments/{id}/progress`：当前版本最近成绩（submittedAt/id 降序）、最高成绩（score/submittedAt/id 降序）、当前版本未提交 attempt 的 id/revision；不返回旧版本汇总。

- 学生 `/assignments/:id`、`/submissions/:id`。
- 管理端（教师角色）`/teacher/submissions`。

### 3. 关键实现

1. 当前版本成绩由独立查询计算，只过滤 `attempt.version_id = current_version_id` 的提交；发布 v2 后最近/最高自然为空，历史接口仍返回 v1 记录。
2. 开始作答复用该版本最新 OPEN attempt，避免页面刷新或跨设备打开产生新 attempt、丢失草稿 revision。
3. 提交详情按固定 `version_id` 读取题面、标准答案和解析；选择题返回 `correctAnswers`/`analysis`，代码题只返回 `referenceBySlot`，不返回 rubric。
4. 代码提交新增“至少一个非空 slot”校验，全空白返回 422；部分空 slot 仍允许，符合未完成答案也可点评的设计。
5. CodeMirror 6 + Java 语言包按 slot 挂载；本地输入 2 秒防抖保存，409 冲突保留本地内容并提示载入服务器草稿，离页前保存并注册 `beforeunload` 提示。
6. 选择题未答可提交，页面先展示未答题数确认；提交复用 Idempotency-Key，内容变化才换新键。
7. AI 点评页初始 2 秒轮询、30 秒后降为 5 秒，离页停止；轮询 URL 带时间戳避免缓存；不显示供应商或底层异常，mock 结果显式标记。
8. 教师每次读取都调用课程内部范围接口，调离后旧页面立即 403；昵称查询失败只降级显示 `学生 #id`，不阻断作答事实读取。
9. 修复 S10-b 遗留问题：Jackson 2 `ObjectNode` 被 Boot 4 的 Jackson 3 序列化成节点内部字段，导致前端读取 `issues.length` 崩溃；反馈改为普通 Java 对象，并补充接口断言。

### 6. 理解问题与精简回答

1. **为什么“当前版本最近/最高成绩”要单独查询，不在历史列表里算？** 历史包含所有版本，当前页只能统计当前版本；独立查询把口径固定在 `version_id`，新版本未作答时不会把旧版本最高分误显示成当前成绩。
2. **为什么开始作答要复用同一版本的 OPEN attempt？** 草稿和 revision 属于 attempt；每次打开页面都新建 attempt 会让跨设备续写变成两份互不相干的草稿。复用后，另一台设备能看到同一 revision，冲突仍由乐观锁处理。
3. **教师范围为什么要每次向课程服务查询？** 教师分配是课程库的事实，作业库缓存可能过期；调离课程后旧页面立即读取会被拒绝，避免把“当前负责课程”当成长期授权。
4. **选择题解析和代码参考实现为什么都只在提交后返回？** 参考答案是作答结果的一部分；提前返回会让学生直接看到答案。提交接口生成不可变 submission 后才通过详情接口暴露，保存草稿和公开题面都不包含这些字段。
