## 数据库与迁移

1. 新建本项目独立库 `bc_course`（utf8mb4_0900_ai_ci），未修改本机其他数据库。
2. 迁移文件 `V1__create_category.sql` 只建 `category` 一表，字段与《07-数据库设计》一致：id、parent_id、name、sort、enabled、created_at、updated_at、revision，索引 `idx_category_parent_sort(parent_id, sort, id)`。
3. **异常与处理**：启动前发现 `bc_course` 中已有另一会话在 01:55 应用的同名 V1 迁移，但校验和不同（其表带 `DEFAULT CURRENT_TIMESTAMP(3)`）。表内容为 0 行。处理方式：
   - 用 `ALTER TABLE` 去掉两列时间默认值，使结构与本仓库迁移文件一致（无数据丢失）；
   - 使用 Flyway `repair` 将历史校验和对齐到本地文件（1389730283）；
   - 未采用删库重建：DROP DATABASE 被工具安全策略拒绝，且无必要。
4. **干净库验证**：新建空库 `bc_course_verify` 启动服务，日志显示 `Successfully applied 1 migration ... now at version v1`；表结构与迁移文件完全一致；`flyway_schema_history` 1 行、checksum 1389730283。
5. **重启幂等**：停止并重启服务后，日志为 `Schema bc_course is up to date. No migration necessary.`，历史表仍为 1 行，未重复迁移。
6. 临时库 `bc_course_verify` 已于 2026-11-19 按用户要求删除，数据库中只保留 `bc_course`。
