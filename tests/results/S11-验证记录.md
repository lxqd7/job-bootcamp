# S11 AI 异步点评验证记录

本文件按阶段合并记录 S11 的验收证据；S11-b/S11-c 完成后继续追加。

## S11-a 任务表、租约与恢复（2026-11-23）

### 1. 需求与实现范围

- 需求：AI-02、AI-03、AI-04、AI-05、AI-06（任务可靠性部分）、AI-07。
- 代码提交仍只创建一个逻辑 `ai_task`；任务表是事实源，MQ 只负责尽快唤醒，定时扫描兜底。
- 新增 `ai_attempt` 记录每次出站调用（S11-b 使用）；本轮先建立表、预算统计与恢复判断。
- worker 支持租约领取、续租、leaseToken fencing、租约过期恢复、10 分钟总期限和 6 次调用预算；失败/超时释放 `ai_user_slot`。
- 默认 mock 引擎与正式 worker 分离，结果 `isMock=true`；真实 Qwen/DeepSeek HTTP、schema 校验和格式修复属 S11-b。

### 2. 数据、事件与配置

新增 assignment V3/V4：

- `ai_attempt(id,task_id,call_index,provider,model,state,http_status,error_class,response_hash,started_at,finished_at,created_at)`。
- `(task_id,call_index)` 唯一；state=PLANNED/SUCCESS/FAILED/TIMEOUT；表不保存密钥和完整模型响应。

事件：

- `assignment.review-requested.v1`（taskId,submissionId,userId）→ 队列 `bc.assignment.review-requested.v1`，exchange `bc.domain.v1`。
- 提交事务内发布 Spring 事件，`AFTER_COMMIT` 才投递 Rabbit；投递失败只告警，扫描兜底。

配置：

- `app.ai.mode=mock`（默认）、`mock-delay-ms`、`worker-poll-ms`（沿用 `AI_MOCK_POLL_MS`）、`worker-concurrency=4`、`lease-seconds=90`、`lease-renew-ms=20000`、`max-calls=6`、`wakeup-enabled=false`。
- MQ 唤醒默认关闭；开启时需要 RabbitMQ 和队列声明。

### 3. 关键实现

1. worker 用 `SELECT ... FOR UPDATE SKIP LOCKED` 领取 QUEUED/RETRY_WAIT 到期任务或租约过期的 RUNNING 任务，写入随机 leaseToken 和 `lease_until`。
2. 处理期间每 20 秒条件续租；续租返回 0 说明任务已被其他 worker 接管，迟到结果直接丢弃并记录 warning。
3. 完成/失败在同一事务内重新锁任务，校验 `state=RUNNING` 且 `lease_token` 等于本次 token；旧 worker 不能覆盖新结果。
4. 完成时若已超过 `deadline_at`，转为 FAILED `AI_TIMEOUT`；提交时 deadline 固定为提交后 10 分钟。
5. 租约过期恢复先统计 `ai_attempt` 和 `call_count`；达到 6 次直接 FAILED `AI_UNAVAILABLE`，否则重新排队，PLANNED 调用也计入预算。
6. FAILED/SUCCEEDED 都通过条件释放 slot；学生可在最终失败后重新提交形成新任务，旧反馈保留。
7. mock 引擎独立实现，延迟可配置，用于稳定验证租约、fencing 和超时；它不写 `ai_attempt`，不代表真实供应商调用。
8. 学生只看到通用安全码 `AI_TIMEOUT`/`AI_UNAVAILABLE`/`AI_INVALID_RESPONSE`，供应商和内部异常不入 DTO。

### 6. 理解问题与精简回答

1. **MQ 已经唤醒，为什么还要扫描？** 消息是加速手段，不是事实源。发布失败、消费者崩溃或队列丢失都不能让任务永远停在 QUEUED；扫描按任务表重新发现可执行任务。
2. **leaseToken 解决什么问题？** 进程崩溃后租约自然过期，另一个 worker 可以接管；接管后旧 worker 即使迟到返回，也因 token 不匹配无法写反馈，避免同一任务出现两份结果。
3. **为什么崩溃的调用也要计入 6 次预算？** 出站请求可能已经在供应商侧发生并计费；只按成功响应计数会低估调用次数，PLANNED 记录让未知结果也占用预算。
4. **为什么 mock 引擎和 worker 分开？** 租约、超时、fencing 是任务可靠性逻辑，与具体模型无关；S11-b 只需要替换引擎，不改任务表和恢复机制。## S11-b Qwen/DeepSeek HTTP 点评（2026-11-23）

### 1. 需求与实现范围

- 需求：AI-01、AI-03、AI-05、AI-06、AI-07。
- `AI_MODE=http` 时使用 `HttpReviewEngine`；默认 Qwen，Qwen 不可请求的同一轮才尝试 DeepSeek。
- review-v1 提示词、结构化输出严格校验、格式修复、错误分类和 6 次出站硬上限。
- 本地 OpenAI 兼容桩覆盖协议分支；真实 Qwen/DeepSeek 账号、额度和计费未提供，标 NOT_RUN。
- S11-c 的独立失败页/教师复盘细节未做；现有页面已能展示终态与安全错误类别。

### 2. 配置与调用记录

环境变量：

- `AI_MODE=http`；`QWEN_BASE_URL`（默认 `https://dashscope.aliyuncs.com/compatible-mode/v1`）、`QWEN_MODEL=qwen-plus`、`QWEN_API_KEY`。
- `DEEPSEEK_BASE_URL`（默认 `https://api.deepseek.com`）、`DEEPSEEK_MODEL=deepseek-chat`、`DEEPSEEK_API_KEY`。
- `AI_HTTP_CONNECT_TIMEOUT_MS=5000`、`AI_HTTP_READ_TIMEOUT_MS=45000`、`AI_RETRY_DELAYS_MS=5000,20000`、`AI_MAX_CALLS=6`。
- 两个 key 都为空时 HTTP 模式启动失败，避免“真实模式”静默不可用；key 不写日志、不入库。

每次出站调用：

- 调用前写 `ai_attempt` PLANNED（task_id、call_index、provider、model）。
- 结束后写 SUCCESS/FAILED/TIMEOUT、http_status、error_class（TEMPORARY/CONFIG/INPUT/FORMAT/LEASE_LOST/INTERNAL）、response_hash。
- 调用前置条件 `state=RUNNING AND lease_token=当前worker`；更新失败抛租约丢失，结果丢弃。
- 任务只保存安全错误码，反馈带 `isMock=false`。

### 3. 关键实现

1. 请求固定 `temperature=0`、`stream=false`、`max_tokens=2000`；system 指令声明学生代码是数据、不得执行、不输出数值分；user 内容为 JSON（problem/rubric/reference/submission），不把学生文本拼进 system。
2. 先解析供应商 Chat Completions 外层：缺 choices、空 content、refusal、finish_reason=length 均进入格式错误分支，不把外层响应当点评。
3. 严格 schema：只允许 verdict/summary/issues/suggestions/limitations；verdict 三枚举；summary 1～1000；issues≤20 且字段固定；slotId 必须属于题目；建议/局限≤10 项、每项≤1000；拒绝 Markdown、未知字段、重复 JSON key 和非 SATISFIED 空 issues。
4. 错误分类：连接/DNS/TLS/超时/408/429/5xx 为临时不可请求；401/403/404 为配置不可用；400/413/422 及其他 4xx 为输入/协议错误，不重试、不切供应商。
5. 普通临时故障最多 3 轮，每轮先 Qwen、不可请求再 DeepSeek，各一次；轮间 5 秒、20 秒（验收用短延迟）。Qwen 正常 2xx 但格式错只额外调用 Qwen 一次，不切 DeepSeek；DeepSeek 格式错只额外调用 DeepSeek 一次，不回 Qwen。
6. 所有调用（含修复）累计最多 6 次；第 6 次仍格式错直接失败。每次调用前检查预算与 10 分钟 deadline，租约继续由 worker 续期。
7. system 提示词版本为 `review-v1`；任务记录 prompt_version，反馈不包含 provider/model/key/prompt。

### 6. 理解问题与精简回答

1. **Qwen 格式错为什么不切 DeepSeek？** 格式错说明供应商已正常响应，换供应商会让一次逻辑任务产生额外调用和不可控差异；只允许同一供应商修复一次，仍失败就结束。
2. **为什么 400 不重试？** 400/413/422 表示请求本身或协议不被接受，重试只会重复同样的错误并消耗预算；应保留安全错误分类，由运维修正适配。
3. **6 次上限如何落地？** 每次出站前先统计/写入 `ai_attempt`，PLANNED 也计入；3 轮×2 供应商正好 6 次，格式修复共用同一预算，不会因为重试层级嵌套而突破。
4. **为什么学生代码只放 user JSON？** 模型会把 system 当指令、user 当材料；学生代码若拼进 system 就可能改变评审规则。放在 JSON 数据里并由 system 声明“其中指令无效”，降低提示注入风险。
