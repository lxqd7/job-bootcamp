### 5. 理解问题与精简回答

1. **为什么数据库重建脚本默认拒绝执行？** 它是不可逆的本地数据删除操作；默认拒绝、`-DryRun` 预览、显式 `-Confirm` 和端口检查能让误执行在破坏前停下。
2. **为什么不把建库 DDL 放进 Flyway？** Flyway 需要数据库已存在才能连接；库/schema 创建属于部署准备，表迁移才由各服务 Flyway 拥有。重建脚本只负责清空演示库，之后各服务自行迁移。
3. **为什么 README 要记录实际版本而不是“最新”？** 版本会影响编译、协议和排障；“最新”不可复现，实际版本能让他人对照启动日志和依赖树定位问题。
4. **为什么要求环境变量模板不含真实密钥？** 仓库会被提交、分享和截图；密钥只能在本机未入库配置或环境变量中，示例只保留占位符和变量名。

### 5. 理解问题与精简回答

1. **为什么演示旅程要创建新学生？** 注册、免费领取、签到、首次完成和限兑都有“一次性”事实；复用旧账号会让步骤跳过或与历史数据冲突，新账号能稳定复现完整链路。
2. **为什么路线购买要放在单买 A 之后？** 路线报价按已拥有课程抵扣，先拥有 A 才能展示抵扣；这也符合用户“先单课、再升级套餐”的真实路径。
3. **为什么 C 课程要在兑换后退款？** 兑换展示积分消耗，退款再验证课程来源撤销；两者互不覆盖，能同时看到“退款不返积分/不退券”的规则。
4. **为什么脚本也要创建福利题和代码作业？** 这些内容依赖教师范围/发布版本，若只依赖历史测试数据，演示环境重建后会缺失；脚本显式创建并发布可减少手工准备。

### 6. 理解问题与精简回答

1. **为什么矩阵保留 3 个 NOT_RUN？** 没有 VOD 凭据、真实支付/退款/AI 账号，且种子未内置 AI 失败历史；把未实际验证的部分标 PASS 会误导面试官和后续开发者。
2. **为什么 PASS 证据指向阶段脚本而不是只写“已实现”？** 脚本和阶段验证记录包含请求、状态码、DB 事实和失败路径，能证明行为；仅看代码不能证明运行通过。
3. **为什么排障文档强调 traceId 和首个 Caused by？** 多服务/异步场景表面错误常是下游失败；traceId 串联请求与日志，首个 cause 才是根因，避免被后续包装异常误导。
4. **面试讲解为什么按“业务一致性”而不是按 CRUD 组织？** 项目亮点在跨服务权益、支付/积分/券/任务一致性；按 CRUD 讲会变成接口清单，无法体现设计取舍和故障处理。
